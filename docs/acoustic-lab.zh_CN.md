# 声音种子实验室

手机打开[生命声场](https://unstone.github.io/life-passport/)，无需安装应用、蓝牙配对、麦克风权限或账号。网页在本地生成声音，无法知道设备是否接收成功；请对照设备显示的序号、数据和CRC判断。

## 使用流程

这版测试固件冷启动直接进入声音接收页。先在安静环境、距离10cm测试，手机媒体音量50%、网页编码音量20%；设备显示削波时降低音量。监听期间保持亮屏。

| 设备操作 | 结果 |
| --- | --- |
| 接收页短按确定 | 暂停／恢复麦克风监听。 |
| 接收页按下键 | 清零计数和上一包显示。 |
| 接收页长按确定 | 停止麦克风，返回工具；选择返回演化即可继续游戏。 |
| 收到有效诊断包 | 显示序号和7字节内容，始终不替换棋盘。 |
| 收到有效key包 | 停止监听，暂停预览还原后的棋盘。 |
| 预览页短按确定 | 应用后仍暂停，再按一次才开始演化。 |
| 预览页长按确定 | 恢复原棋盘，回到接收页继续监听。 |

工具中的声音接收入口可以重新启动监听。游戏运行时常亮，暂停后仍按30秒调暗、90秒熄屏、5分钟深睡处理。关闭 `CONFIG_LIFE_ACOUSTIC_LAB_BOOT` 可恢复冷启动直接运行R五连块。

## LP1协议

棋盘固定36列×32行，规则B3/S23。10位、不区分大小写的36进制key确定可复现初始棋盘；[LP1-B1扩展](world-editor.zh_CN.md)进一步传输任意编辑棋盘，并支持PC／手机浏览器收音。下表定义原有世界码／诊断短包。

| 字节 | 含义 |
| --- | --- |
| 0–1 | ASCII `LP`。 |
| 2 | 版本 `1`。 |
| 3 | 低2位类型：诊断=0、key=1；第2位环绕；第3–4位速度索引，对应 `{125,200,500,1000}` ms；第5–7位为零。诊断包标志必须全零。 |
| 4 | 序号0–255。 |
| 5–11 | 7字节诊断内容，或小端整数key，必须小于 `36^10`。 |
| 12–15 | 前12字节的IEEE CRC32，小端。 |

LP1使用xorshift64*：状态取key，零值替换为 `0x9E3779B97F4A7C15`；依次异或右移12、左移25、右移27，再乘 `2685821657736338717`，保留低64位。按行遍历1152个格子，每个输出对100取模，小于28为活细胞。棋盘CRC按144字节、逐行、每格低位优先的位图计算。[参考向量](../tests/audio_vectors.json)验证C、Python和JavaScript的一致性。

GGWave提供调制、DSS和Reed–Solomon纠错。设备仅启用 `AUDIBLE_FASTEST` 与 `DT_FASTEST`，固定 **16字节**，24kHz单声道I16、512点FFT。浏览器采用相同频率间隔的48kHz／1024点标准编码器，并适配实际AudioContext输出采样率。LP1没有超声模式或外层擦除码；CRC用于拒绝损坏数据，不提供身份认证。

录音通过原有BSP分块处理，不保存录音。独立任务拥有麦克风和GGWave，发布加锁的状态快照，只向应用所有者队列提交验证后的种子；LVGL操作继续使用BSP锁。离开页面时等待任务结束再休眠编解码器；初始化、读取、解码和清理错误会明确显示，需要主动重试。连续相同数据包只增加重复计数，不重复应用；待确认预览期间停止监听。

## 手动验收

公开网页的「用例与记录」包含相同编号，并可将手动结果导出为JSON。记录是人工观察，不是自动接收回执。

| 编号 | 操作 | 预期观察 |
| --- | --- | --- |
| TC01 | 静音监听10秒。 | 通过数不增加，记录环境dBFS基线。 |
| TC02 | 距离10cm播放1000Hz。 | 信号升高，主频约1000Hz、允许约±47Hz；通过数不增加。 |
| TC03 | 播放1000–7000Hz分段扫频。 | 逐档记录主频和信号，包括弱频段与削波。 |
| TC04 | 分别播放双音、六音测试。 | 信号变化，最强主频属于输入音调；单个主频不能证明全部音调已识别。 |
| TC05 | 设备清零，六音发送一次全部00。 | 序号与网页一致，7字节为 `00000000000000`，棋盘不变。 |
| TC06 | 依次发送FF、55AA交替、00–06递增。 | 7字节逐位一致，包括高位；棋盘不变。 |
| TC07 | 双音重复TC05／06。 | 比较与六音的实际成功率和耗时。 |
| TC08 | 清零，随机诊断数据发送10次。 | 通过减重复理想为10，末包序号／内容与网页一致；记录实际数值。 |
| TC09 | 发送故意错误CRC的诊断包。 | 通过数不增加，棋盘不变；拒绝数可能增加。 |
| TC10 | 暂停监听，网页先循环播放，2秒后恢复监听。 | 能接收后续一轮；相同重复包计数，不改变棋盘。 |
| TC11 | 发送 `0123456789`，预览后停止声音，对照细胞数／CRC／图案，再按两次确定。 | 初始棋盘一致；第一次确定应用并暂停，第二次才演化。 |
| TC12 | 发送 `ZZZZZZZZZZ`，预览时长按确定。 | 不溢出、不重启；取消后恢复旧棋盘和接收页。 |
| TC13 | 10／30／50cm各发10包；再单独改音量或加入正常说话声。 | 记录真实成功数、削波和解码耗时，每次只改一个条件。 |
| TC14 | 停止播放，监听暂停／恢复／退出／重进10次。 | 无残留声音、按键失效或重启，返回游戏运行时常亮。 |

先做TC01、TC02、TC05、TC11。TC08／13记录手机／浏览器、距离、网页音量、手机媒体音量、声码、通过／重复／拒绝数和最大解码耗时。「拒绝」包括解码失败，不能统计每个未听到或丢失的数据包；不能仅凭信号强度判定传输成功。

## 复现

使用 `--recurse-submodules` 克隆，或执行 `git submodule update --init --recursive`。启用ESP-IDF 5.5.3，并通过fnm选择Node 22.22.3，执行 `./tools/validate.sh`，包括仓库／主机／原生LVGL检查、固件和合并镜像校验、浏览器WASM与原生声音解码互通测试。参见[网页命令](../site/README.zh_CN.md)与[GGWave集成](../components/ggwave/README.zh_CN.md)。

执行 `npm run build --prefix site` 后，仅将 `site/dist/` 发布到 `gh-pages` 分支，添加 `.nojekyll`，GitHub Pages选择该分支根目录。资源采用相对URL，支持 `/life-passport/` 路径。先验证公开网页与下载的WAV，再将已验证的合并固件从 **0x0** 烧录。交付测试报告记录精确哈希、真机结果与仍待手机／环境验证的项目。
